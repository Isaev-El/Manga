# Задания по сервису Catalog

Каждое задание — отдельная ветка и pull request. Изменили модель — добавьте миграцию.

## 1. Outbox-процессор
Сейчас события копятся в `outbox_messages`, и их никто не обрабатывает.
Сделать `BackgroundService`, который раз в 5 секунд берёт до 20 необработанных сообщений
(`ProcessedOnUtc IS NULL`, по возрастанию `OccurredOnUtc`), пишет их в лог и проставляет `ProcessedOnUtc`.

**Готово, если:** после создания манги через несколько секунд в логе есть `MangaCreated`,
а у записи в таблице заполнено `ProcessedOnUtc`.

## 2. Unit of Work
Разобраться, как работает `UnitOfWork`, и расширить его: если при сохранении произошла ошибка
уникальности (`DbUpdateException` от Postgres с кодом `23505`), выбрасывать понятное исключение,
которое API превращает в 409 Conflict.

**Готово, если:** попытка создать дубликат (например, жанр с существующим именем после задания 4)
возвращает 409 с понятным текстом.

## 3. Редактирование тайтла
Метод `Manga.UpdateDetails(title, author)` с теми же проверками, событие `MangaUpdated`,
эндпоинт `PUT /api/manga/{id}`.

**Готово, если:** событие пишется в outbox только когда что-то действительно изменилось.

## 4. Управление жанрами
`POST /api/genres` и `DELETE /api/genres/{id}`.
Нельзя создать два жанра с одинаковым именем (без учёта регистра),
нельзя удалить жанр, который используется хотя бы одной мангой.

**Готово, если:** ошибки возвращаются как 400/409 с понятным текстом, а не 500.

## 5. Статусы и переходы
Методы `PutOnHiatus()` и `Resume()`. Правила: завершённую мангу нельзя заморозить,
продолжить можно только замороженную. На каждый переход — своё событие и эндпоинт.

**Готово, если:** unit-тесты покрывают все разрешённые и запрещённые переходы.

## 6. Поиск и пагинация
`GET /api/manga?search=&status=&genreId=&page=1&pageSize=20`.
Ответ: `{ "items": [...], "totalCount": 123 }`. `pageSize` не больше 100.

**Готово, если:** фильтры комбинируются между собой.

## 7. Unit-тесты домена
Проект `tests/Catalog.Domain.Tests` (xUnit). Проверить инварианты `Manga` и `Genre`
и то, что `Create` и `Complete` порождают нужные события.

**Готово, если:** тесты не используют ни базу, ни EF Core и запускаются через `dotnet test`.

## 8. Оптимистичная блокировка (повышенная сложность)
Два пользователя одновременно меняют одну мангу — второй не должен молча затереть изменения первого.
Использовать системный столбец Postgres `xmin` как токен конкурентности, возвращать 409 Conflict.

**Готово, если:** есть сценарий с двумя параллельными изменениями, второе получает 409.

## 9. Перестановка страниц
`PUT /api/chapters/{id}/pages/order` с новым порядком страниц (список текущих номеров, например `[3, 1, 2]`).
Только в черновике; в списке должны быть все страницы ровно по одному разу.

**Готово, если:** после перестановки `GET /api/chapters/{id}` возвращает страницы в новом порядке,
а неполный или повторяющийся список даёт 400.

## 10. Снятие главы с публикации
`Chapter.Unpublish(reason)` и `POST /api/chapters/{id}/unpublish`. Глава возвращается в черновик,
причина обязательна, поднимается событие `ChapterUnpublished`.

**Готово, если:** после снятия страницы снова можно менять, а в outbox есть событие с причиной.

## 11. Только опубликованные главы для читателя
Сейчас `GET /api/manga/{id}/chapters` отдаёт и черновики. Добавить параметр `?includeDrafts=true`:
по умолчанию возвращать только опубликованные главы.

**Готово, если:** читатель черновиков не видит, а с параметром они возвращаются.
